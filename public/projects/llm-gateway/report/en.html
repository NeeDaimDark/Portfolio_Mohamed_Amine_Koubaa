At a glance

LLM Gateway sits between the applications of a company and the providers of AI models. Instead of each product holding its own provider keys and calling models directly, every AI request goes through the gateway.

The gateway decides which model answers, switches to a backup model if a provider fails, checks the request against budgets and usage rules, and records cost, duration and outcome. Administrators manage all of this from a web console in French, English or Arabic, in a light or dark theme.

The platform runs in development, test and production environments and serves several products of the same company.

Who it's for

Product teams

Developers connect their application once to the gateway and get access to many AI models, with a developer guide and ready-to-use code examples.

Platform administrators

They organise the company into organisations, teams and applications, connect providers and decide which models each application uses.

Managers and finance

They follow AI spending per application, model and provider, set budgets and receive alerts before a limit is reached.

Security and compliance

They define usage rules, mask sensitive data in requests and review an audit log of administrative actions.

The problem it solves

Before the gateway, each product called AI providers on its own. Provider keys were spread across services, nobody had a shared view of what AI was costing, and when something went wrong there was no trace of which request, model or application was involved.

The gateway brings these calls under one roof: one place to hold provider access, one set of rules, one cost view and one history of every request.

Main features

Routing with backup models

Each application route has an ordered chain of models. If the first one fails or is unavailable, the request moves to the next one automatically.

Live streaming of answers

Answers can be streamed word by word to the application, with retries on provider errors and a time limit on every request.

Budgets and alerts

Spending caps per organisation, team or application, with a forecast, an alert at a chosen threshold and an optional hard block once the cap is reached. Alerts arrive by email and in the console.

Usage rules

Rules attached to routes limit request rate and answer size, block prompt-injection attempts, mask personal or banking data and control retries.

Observability

Every request is traced: model used, duration, tokens, cost and each step from policy check to model answer, shown as a timeline.

Cost analytics

Cost, requests, errors and latency over time, broken down by application, model and provider, with week-on-week comparisons and budget projections.

AI tool servers (MCP)

External tool servers can be registered so that models call business tools during a conversation. Tools are discovered automatically, health-checked and classified by risk level.

Model arena

Two models can be tested side by side on the same prompt to compare answers before choosing one for an application.

Access and security

Sign-in with user accounts, application API keys shown only once, encrypted provider keys, admin access requests and a full audit log.

How it works

An application sends a request

The product calls its own route on the gateway with its API key, as it would call an AI provider.

Rules and budgets are checked

The gateway identifies the application, applies the rules attached to its route and checks that its budget allows the call.

A model is chosen

The gateway sends the request to the first model of the route's chain and moves to a backup model if the provider does not answer.

Tools are called when needed

If the model asks for a business tool, the gateway runs it on the registered tool server and gives the result back to the model.

The answer is returned and recorded

The answer goes back to the application, streamed or in one block, while cost, tokens, duration and every step are saved for the console.

Technologies

Interface

Angular MaterialProvides the interface components of the console.
ngx-translateServes the console in French, English and Arabic, including right-to-left layout.

Server & APIs

PythonLanguage of all the gateway services.
AWS LambdaRuns each gateway service on demand, without servers to manage.
Amazon API GatewayExposes the gateway and console APIs to applications and users.
Server-Sent EventsStreams model answers to applications as they are produced.

Data

MongoDBStores organisations, routes, rules, budgets and the usage record.
Amazon SQSQueues budget alerts before they are sent by email and in-app notification.

AI

AI model providersOpenAI, Anthropic, DeepSeek, Groq and NVIDIA models are reachable through one interface.
Model Context Protocol (MCP)Connects models to external tool servers they can call during a conversation.
LangfuseKeeps detailed traces of model calls for analysis.

Cloud & security

Amazon CognitoHandles user sign-up and sign-in to the console.
AWS KMS and VaultEncrypt and store provider keys and other secrets.
Terraform and TerragruntDescribe the cloud infrastructure of each environment as code.
GitLab CITests, builds and deploys every service automatically.

Quality

pytestRuns the automated tests of the gateway services.
VitestRuns the automated tests of the console.

What it brings

Costs under control

AI spending is visible per application, model and provider, and budgets stop overspending before it happens.

Fewer outages

Backup models take over when a provider fails, so products keep answering.

Safer use of AI

Provider keys stay in one protected place, sensitive data can be masked and every administrative action is logged.

Faster integration

A product connects once and can then change models or providers from the console, without changing its code.
